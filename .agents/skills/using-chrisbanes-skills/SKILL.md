# Skill routing

Use the smallest focused skill set that matches the task. Inspect the repository before applying guidance.

- Compose state/effects/navigation lifecycle → `compose-state-and-effects`
- Compose recomposition/jank/stability/frame pacing → `compose-performance`
- Compose UI tests → `compose-ui-testing-patterns`
- Coroutines/Flow/cancellation/events → `kotlin-concurrency-and-flow`
- Public Kotlin API or model design → `kotlin-api-design`
- Kotlin control-flow/readability/refactoring → `kotlin-control-flow`
- Android benchmark comparisons → `android-benchmark-comparison`
- Gradle execution or repeated build failures → `gradle-run`
- Planning before implementation → `to-plan`
- Multi-step repository shepherding/review → `shepherd`

Do not activate unrelated skills merely because they are available. AERGIS project-specific skills remain authoritative when they impose stricter evidence, safety, branch, or device-validation rules.
